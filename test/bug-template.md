# BUG 提交模板

> 使用说明：在分支上提 bug 时，复制本模板内容到 git 提交（issue 描述 / commit message / bug 文档）中，按 `【 】` 提示填写后提交。
> 标题格式建议：`[BUG-序号][严重程度] 一句话描述现象`，例如：`[BUG-003][S2] 未登录直接访问 /archive 未被拦截，可直接进入档案页`。
> 截图统一存放在 `test/screenshots/` 目录（如目录不存在请创建），命名规则：`BUG序号_步骤编号_描述.png`。

---

## BUG标题

【一句话描述 bug 现象，包含出错的功能点和错误表现】

## 所属分支

【提交 bug 所在的代码分支，如 feature-wang-qing-frontend】

## 复现环境

| 项目 | 内容 |
|---|---|
| 操作系统 | 【如 Windows 11】 |
| 浏览器及版本 | 【如 Chrome 120】 |
| 访问地址 | 【如 http://localhost:5173】 |
| 前端启动方式 | 【如 frontend 目录下 npm install && npm run dev】 |
| 是否已登录 | 【是/否，如涉及登录态需注明登录账号输入内容】 |

## 复现步骤

1. 【步骤1：如打开 http://localhost:5173，进入登录页】
2. 【步骤2：如账号输入框保持为空】
3. 【步骤3：如密码输入框输入 123456，点击登录按钮】
4. 【步骤N】

## 预期结果

【按需求/测试用例应表现的正确结果，如：登录被拦截，停留在登录页并提示"账号不能为空"】

## 实际结果

【实际观察到的错误表现，如：页面无任何提示直接跳转到 /archive】

## 截图存放位置

- 截图目录：`test/screenshots/`
- 截图文件：
  - 【BUG序号_步骤编号_描述.png —— 简要说明该截图内容】

## 优先级

【P0 紧急（阻塞主流程，需立即修复）/ P1 高（本次迭代内必须修复）/ P2 中（可安排在本迭代或下迭代）/ P3 低（有空闲时修复）】

## 严重程度

【S1 致命：功能完全不可用/白屏/崩溃，无替代方案】
【S2 严重：主要功能异常、跳转错误，影响使用】
【S3 一般：次要功能异常或提示文案不友好】
【S4 轻微：界面/样式瑕疵、不影响功能】

> 备注（可选）：填写关联测试用例ID（如 TC-LOGIN-00X）、日志片段、初步原因分析等信息，便于开发定位。
